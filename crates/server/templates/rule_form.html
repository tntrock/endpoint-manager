{% else if kind == "forbidden_image" %}

不寫版本標籤就比對所有版本：nginx 符合 nginx:1.27 與 docker.io/library/nginx:1.27；nginx:1.1* 只符合 1.1 開頭的版本。只套用到 Linux 裝置；沒有回報容器資料的裝置不適用。

{% else if kind == "container_privilege" %}

執行中的容器符合任一勾選條件就算違規。Kubernetes 的容器讀不到特權與主機網路設定，不計入檢查，違規細節會註明幾個無法判斷。只套用到 Linux 裝置。

{% else if kind == "unpinned_image" %}

執行中的容器使用的映像沒有版本標籤、或標籤是 latest，而且沒有用 digest（@sha256:…）固定時算違規。LXC／Incus 系統容器不檢查。只套用到 Linux 裝置。

{% else if kind == "unquoted_service_path" %}

服務的執行檔路徑沒有用引號包起來、路徑含有空白，而且不在 Windows 目錄底下時算違規。例如 C:\Program Files\My App\svc.exe：有權限在 C:\ 建立 Program.exe 的人可以讓服務以 SYSTEM 身分執行它。修正方式是在服務設定的路徑前後加上引號。

{% else if kind == "open_share" %}

檢查 Windows 的 SMB 共用、Linux 的 Samba 與 NFS。Windows 以共用權限與資料夾權限較小的一邊判斷；Guest 帳號啟用時，給 Everyone 的權限也算匿名。NFS 的來源是 * 時算匿名。常見的正常情況：IT 的軟體散布共用（通常只能讀）、部門共用資料夾（所有人可寫入是刻意的），用例外排除。

{% else if kind == "extra_root_account" %}

root 以外還有 UID 0 的帳號時算違規：UID 0 就是 root，可能是有人留下的後門帳號。某些設備廠商的維護帳號可以加入例外。

{% else if kind == "update_policy" %}

裝置的更新原則被改動（例如 GPO 覆蓋）或套用失敗時算違規；不受管的裝置算符合。
