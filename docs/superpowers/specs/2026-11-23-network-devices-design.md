# 網路設備資訊（由分點快取主機以 SNMP 收集）設計

日期：2026-11-23。狀態：使用者已審閱同意（2026-11-23）。
來源：`docs/roadmap.md`「網路設備資訊」。使用者決定（2026-11-23）：提前做，**不做主動掃描**。

標「（設計者決定）」的項目是我做的決定，審閱時可以推翻。

## 1. 目的

1. **看得到網路設備**：交換器、路由器、AP 的型號、序號、韌體版本、開機時間、每個埠的狀態。
2. **知道每台電腦接在哪裡**：哪台交換器的哪個埠、哪個 VLAN，以及什麼時候換過位置。
3. **找出沒裝 Agent 的設備**：交換器看得到、但不屬於任何已註冊電腦的 MAC 位址。
4. **提供端點以外的證據**：交換器的資料不是電腦本身產生的，有本機管理員權限的人改不了。之後的「本機資料竄改偵測」會用它來比對 Agent 回報的資料（§9）。

### 1.1 範圍

**做：**
- 分點快取主機用 **SNMP 唯讀** 查詢管理員登錄的網路設備。
- 支援 SNMP v2c 與 v3（authPriv：SHA／SHA-256 驗證、AES-128／AES-256 加密）。AES-256 有兩種金鑰延伸算法：net-snmp 等多數廠牌用 Blumenthal，Cisco 用 Reeder，所以分成「AES-256」與「AES-256（Cisco）」兩個選項（實作時發現）。
- 只讀標準 MIB，不綁定廠商：
  - SNMPv2-MIB：系統資訊。
  - ENTITY-MIB：型號、序號、韌體。
  - IF-MIB：介面。
  - BRIDGE-MIB、Q-BRIDGE-MIB：MAC 位址表。
  - IP-MIB：ARP 表。
  - LLDP-MIB：鄰居。
- 後台：
  - 網路設備清單與詳情。
  - 電腦的「網路位置」。
  - 未管理設備清單。
  - 總覽的「需要處理」。

**不做：**
- **主動掃描**：不 ping、不掃埠、不掃網段。只查詢管理員明確登錄的設備 IP。
- SNMP 寫入（改設定、關埠）。
- 接收 SNMP trap。
- 流量統計圖（埠的流量計數器）。
- 讀無線控制器的用戶端清單（各廠商的私有 MIB）。
- 設定檔備份。
- 讓 Agent 收集網路資料。

## 2. 誰來收集

- **由據點的快取主機收集**：它已經在每個分點、能連到當地的管理網段，也已經有憑證和與中央的連線。
- **沒有快取的據點收集不到**（設計者決定）。總部要收集，就在總部也裝一台快取主機；只做收集、不放套件也可以。
  - 也可以改成讓中央直接查詢總部的設備，但這樣中央要對內網發 UDP，部署要求變多，所以第一版不做。
- 快取主機需要能用 UDP 161 連到設備的管理 IP。README 要寫防火牆設定。
- 建議在設備上建立唯讀的 community 或 v3 使用者，只開放需要的 MIB。

## 3. 帳密保存

- SNMP 帳密存在中央，**加密保存**：
  - 演算法：ChaCha20-Poly1305。
  - 金鑰：新的環境變數 `EM_SECRET_KEY_FILE`，指向一個 32 位元組的金鑰檔。
  - 安裝說明會附產生金鑰的指令。
  - 沒設定金鑰時，網頁不能新增帳密，並說明原因。
- 帳密獨立成一份清單，多台設備可以共用同一組（通常整個公司用同一組）。
- 網頁上**只能寫、不能讀**：
  - 編輯時欄位留空表示不變。
  - 稽核紀錄不記內容。
- 中央在快取報到的回應裡附上**該據點**設備的帳密：
  - 走 mTLS。
  - 快取只放記憶體，不寫入磁碟。
  - 其他據點的快取拿不到。
- 金鑰輪替第一版不做，README 說明。

（設計者決定。另一個做法是帳密只放在各分點快取的本機設定檔，中央完全不經手。缺點是每個分點都要登入主機修改，所以沒選。）

## 4. 收集內容與頻率

| 項目 | MIB | 頻率（預設） |
|---|---|---|
| 系統：名稱、描述、位置、開機時間、`sysObjectID` | SNMPv2-MIB | 15 分鐘 |
| 實體：型號、序號、韌體版本 | ENTITY-MIB | 15 分鐘 |
| 介面：名稱、描述、類型、管理／運作狀態、速度、最後變動時間、MAC、VLAN | IF-MIB、Q-BRIDGE-MIB | 15 分鐘 |
| LLDP 鄰居：本機埠、對方名稱、對方埠、對方管理 IP | LLDP-MIB | 15 分鐘 |
| MAC 位址表：MAC、VLAN、埠 | BRIDGE-MIB、Q-BRIDGE-MIB | 5 分鐘 |
| ARP 表：IP、MAC、介面 | IP-MIB（舊設備用 RFC1213） | 5 分鐘 |

- 交換器預設 300 秒沒看到就把 MAC 從表上移除，所以 MAC 表每 5 分鐘讀一次，「表上有」大致等於「5 分鐘內有傳過資料」。
- 兩個頻率在「網路設備」頁可以調整，下限 1 分鐘、上限 24 小時（實作時改放這裡：「報到與收集」頁是給 Agent 的設定）。
- **Cisco 的 MAC 表要逐個 VLAN 查詢**：v2c 用 `community@vlan`，v3 用 context `vlan-N`。設備的 `sysObjectID` 是 Cisco 時自動這樣做，也可以在設備設定裡手動開關。
- 查詢限制，保護設備與 WAN（設計者決定）：
  - 每台快取同時查 4 台設備。
  - 每次請求逾時 2 秒，重試 2 次。
  - GETBULK 每次 25 筆。
  - 單台設備一輪最長 120 秒。

## 5. 協定（`protocol::netdev`）

- **`CacheCheckinResponse` 新增 `snmp: Option<SnmpJob>`**（`#[serde(default)]`）：
  - `SnmpJob { devices, system_interval_secs, table_interval_secs }`
  - `devices` 的每一筆：`{ id, address, port, credential, cisco_vlan_mode, poll_now }`
  - 舊版快取不認得這個欄位，直接忽略。
  - 舊版中央不送這個欄位，新版快取就不收集。
- **`POST /v1/cache/netdata`**：每台設備每輪一個請求，gzip 壓縮，上限沿用其他上傳的 5 MB。
  - 內容：
    - `device_id`、`polled_at`、`kind: system | tables`
    - `error: Option<String>`
    - `system`、`entities`、`interfaces`、`lldp`（`system` 輪才有）
    - `fdb`、`arp`（`tables` 輪才有）
  - 每次上傳的是完整快照，中央自己算差異（設計者決定：比上傳差異簡單，也不會因為一次失敗而不同步）。
- 中央只接受快取所屬據點的設備的資料。

## 6. 中央

### 6.1 資料表

```
snmp_credentials
  id, name (唯一), version ('v2c' | 'v3')
  secret_enc            加密後的 JSON：community，或 v3 的 user／auth／priv
  created_at, updated_at

net_devices
  id, site_id, name, address, port (預設 161), credential_id
  enabled, cisco_vlan_mode ('auto' | 'on' | 'off')
  sys_name, sys_descr, sys_location, sys_object_id, uptime_secs
  model, serial, firmware
  last_polled_at, last_ok_at, last_error, consecutive_failures

net_interfaces
  device_id, if_index (主鍵)
  name, alias, kind, admin_up, oper_up, speed_mbps, mac, pvid, last_change_at
  role ('auto_edge' | 'auto_uplink' | 'edge' | 'uplink')   自動判斷，可手動覆寫
  lldp_neighbor          JSON：對方名稱、埠、管理 IP

net_mac_sightings        目前在表上的 MAC
  device_id, if_index, mac, vlan (主鍵), first_seen, last_seen

net_arp
  device_id, ip, mac (主鍵), first_seen, last_seen

endpoint_locations       電腦的位置歷史
  id, endpoint_device_id, mac, net_device_id, if_index, vlan, started_at, ended_at

net_known_macs           標記為「已知」的未管理設備
  id, match ('mac' | 'oui' | 'port'), value, note, created_by, created_at
```

### 6.2 上行埠判斷

MAC 出現在上行埠，不代表設備就接在那裡。符合下列任一條件，就自動判定為**上行埠**：

1. LLDP 鄰居是已登錄的網路設備，或對方宣告自己是橋接器、路由器。
2. 這個埠上同時有 10 個以上的 MAC（設計者決定的門檻；接了下游小交換器或 AP 的埠會有很多 MAC）。

- 管理員可以在設備詳情手動把埠設成「上行」或「端點」，覆寫自動判斷。
- 某個 MAC 只出現在上行埠時，位置顯示「經由 交換器X 的 埠Y（下游有未登錄的交換器或 AP）」。

### 6.3 對應電腦

- 用 Agent `network` 區段裡每張網卡的 MAC 比對。
- 舊版 Agent 沒有 `network` 區段時，改用 ARP 表的 IP 比對，並標示「由 IP 推測」。
- 一台電腦同時出現在多個埠時（例如有線加上走 AP 的 Wi-Fi），全部列出。
- 位置變了（換埠、換交換器、換 VLAN）就結束舊的一段，開一段新的。時間軸顯示「網路位置變更」。

### 6.4 未管理設備

同時符合下列條件，就列入**未管理設備**：

- 24 小時內出現在某個端點埠的 MAC 表上，或出現在據點網段內的 ARP 表上。
- 不是任何使用中電腦的網卡 MAC。
- 不是已登錄網路設備的介面 MAC。
- 不符合 `net_known_macs`：
  - 可以用單一 MAC、廠商前綴（例如所有印表機），或某個埠（例如會議室的埠）標記為已知。
  - 標記時要附註說明。

清單顯示：
- MAC、IP（從 ARP）、廠商、交換器與埠、VLAN、第一次與最後一次看到的時間。
- MAC 是隨機產生的（本機管理位址，手機常見）時加註。

**廠商名稱**：用 IEEE 的 OUI 清單，隨伺服器一起發佈，可以替換成新版（設計者決定）。

### 6.5 保存

- `net_mac_sightings`、`net_arp`：最後一次看到超過 30 天就刪除。
- `endpoint_locations`：365 天，跟多重連線紀錄相同。
- 網路設備刪除時，相關資料一併刪除。

## 7. 後台

- **新頁面「網路設備」**（`/netdevices`，只限平台管理員）：
  - 清單：名稱、據點、IP、型號、韌體、開機時間、狀態（正常／無法連線 N 次／從未成功）、最後查詢、埠的使用數。
  - 新增、編輯、停用、刪除。存檔後下一次快取報到時（最多 60 秒）會立即查詢一次。
  - 「SNMP 帳密」區塊：新增、編輯、刪除；被設備使用中的帳密不能刪除。
- **設備詳情**：
  - 系統資訊與實體資訊。
  - 埠的列表：名稱、描述、狀態、速度、VLAN、角色、LLDP 鄰居、接著的電腦（連結）或未管理設備數。
  - 最近一次錯誤訊息，例如「逾時：請確認快取主機能連到 UDP 161」「驗證失敗：請確認帳密」。
- **未管理設備**（`/netdevices/unmanaged`）：
  - 依據點篩選，可以標記為已知。
  - 已知清單另開分頁，可以取消標記。
- **電腦的裝置頁**，「網路」分頁新增「網路位置」：
  - 目前的交換器、埠、VLAN、最後看到的時間，以及位置歷史。
  - 群組管理員看得到自己電腦的位置，但看不到網路設備頁。
- **搜尋**：輸入 MAC 或 IP 也會找到網路設備與未管理設備（僅平台管理員）。
- **總覽「需要處理」**（平台管理員）：
  - 網路設備無法連線：連續 3 輪失敗，嚴重度高。
  - 新出現的未管理設備：嚴重度低，顯示台數。
- **通知**：第一版不做（實作時決定）。現有的通知管道是以「電腦的違規事件」為單位，網路設備放不進去，要另外設計。先只在總覽「需要處理」顯示。

## 8. 快取程式

- 新背景工作：依 `SnmpJob` 排程，每台設備分別記下兩種輪次的下一次時間。
- 帳密只放記憶體。
- 中央要求的「立即查詢」（`poll_now`）優先處理。
- SNMP 用戶端套件（設計者決定，實作初期再驗證）：
  - 改用 `async-snmp`（實作時決定）：純 Rust 實作 v3 加密，不需要 OpenSSL；加密套件的版本與專案其他部分一致；內建 SNMP agent，測試可以在同一個行程模擬 v2c 與 v3 交換器。
- 快取的網頁 `/caches` 顯示每台快取負責幾台設備、最近一輪是否成功。

## 9. 之後用在竄改偵測（不在這份規格的實作範圍）

有了交換器的資料，就能比對兩件電腦本身改不了的事：

1. **Agent 沒回報，但電腦還在網路上**：電腦的 MAC 還出現在交換器上，Agent 卻超過報到期限沒回報，可能是 Agent 被停掉了。
2. **Agent 回報的位址和交換器看到的不一致**：例如回報的 IP 跟 ARP 表不符、回報的網卡 MAC 從沒出現在任何交換器上。

這部分寫進改寫後的「本機資料竄改偵測」規格。

## 10. 測試

- **protocol**：舊版快取回應沒有 `snmp` 欄位時可以解析；`netdata` 往返。
- **中央單元測試**（純函式）：
  - 上行埠判斷：LLDP、MAC 數門檻、手動覆寫。
  - 電腦對應：用 MAC、用 IP 推測、多個位置。
  - 位置歷史：換埠、沒變。
  - 未管理設備：排除電腦、網路設備、已知 MAC／前綴／埠；隨機 MAC 標示。
  - 帳密加密往返，金鑰不同時解不開。
- **中央整合測試**：
  - 只有該據點的快取拿得到帳密。
  - 其他據點設備的資料被拒絕。
  - 無法連線時出現在「需要處理」，連到後消失。
  - 權限：群組管理員看不到網路設備頁、看得到自己電腦的位置。
  - CSRF。
- **快取程式**：
  - 測試裡啟動一個假的 SNMP v2c 設備（UDP，依錄好的 walk 檔回應），包括 Cisco 逐 VLAN 查詢。
  - 驗證收集結果與排程。
- v3 authPriv 的各種演算法組合，改用 `async-snmp` 內建的 agent 在測試裡驗證，不需要另外的 CI 工作。
- **展示環境**：`emdemo` 塞入幾台交換器、埠與未管理設備，讓網頁有東西可看。

## 10.1 第二期實作時的決定

- 電腦的網卡 MAC 由 `device_network` 的觸發器同步到 `device_macs`，比對時不用每次展開 JSON。
- `net_interfaces.mac_count` 記這個埠上一輪學到幾個 MAC；上行埠的判斷寫成 SQL 函式 `net_port_is_uplink(role, mac_count)`，查詢與存檔共用。
- 自動判斷的 LLDP 上行埠不把「IP 電話」算進去（電話內建小交換器，也會宣告 bridge）。
- 「搜尋 MAC 或 IP 也找到網路設備與未管理設備」先只做在未管理設備頁的篩選（MAC、IP、廠商），頂端的全站搜尋之後再加。
- 廠商清單：伺服器內建一份從 IEEE `oui.csv` 整理的精簡清單（約 4 萬筆，壓縮後約 390 KB）；`EM_OUI_FILE` 可以指定新版的 `oui.csv`。

## 11. 分期

1. **設備與系統資訊**：
   - 協定、資料表、帳密加密。
   - 網路設備頁、快取輪詢系統／實體／介面／LLDP。
   - 無法連線的告警。
2. **MAC 表與 ARP**：
   - 上行埠判斷、電腦的網路位置與歷史。
   - 未管理設備、廠商名稱、已知標記、搜尋。
3. **README 與展示資料**：部署說明（防火牆、建立唯讀帳號的範例）、emdemo。

韌體版本過舊的合規規則不放在第一版（設計者決定）：各廠商的版本字串格式差很多（例如 `15.2(7)E8`），要另外設計比對方式。第一版先在清單上顯示韌體版本，可以排序與篩選。
