# 腳本與套件簽章 第一版 設計

## 1. 目的

現在 Agent 只執行伺服器下發、而且 SHA-256 相符的腳本與套件。雜湊只能證明「內容沒在傳輸中被改」，證明不了「是我們核准的內容」：伺服器（或它的資料庫）一旦被攻破，攻擊者可以自己建立腳本、在資料庫裡標成已核准，或上傳一個惡意安裝檔，所有端點都會以 SYSTEM／root 執行。

這一版讓端點只執行**由伺服器以外的金鑰簽章**的腳本與套件。簽章金鑰放在管理者自己的電腦（建議離線媒體），伺服器只轉送簽章，偽造不了。

### 1.1 範圍

- Ed25519 簽章；新工具 `endpoint-sign` 產生金鑰與簽章。
- 簽章對象：**腳本**（遠端指令）與**派送套件**（安裝與移除）。兩者都是在端點執行任意程式碼的途徑，只保護其中一個沒有意義。
- Agent 設定了信任的公鑰，就**強制**要求簽章；沒設定時行為跟現在一樣（相容）。
- 伺服器：儲存與下發簽章、下載「簽章請求」、上傳簽章、顯示哪些端點強制簽章。

不在範圍、由設計者決定接受的風險：

- 重新開機、關機、重新收集、立即套用這些固定動作不簽章。被攻破的伺服器可以讓電腦重開機，但不能執行程式碼。
- Windows Update 原則不簽章（最多延後更新，不能執行程式碼）。
- 伺服器仍然決定**哪些**端點執行**哪個已簽章**的腳本或套件。簽章證明的是「這段內容經過信任的人審核」，不是「這次要對這些電腦執行」。所以只對審核過、可以安全重複執行的內容簽章。
- 不做金鑰階層或線上換金鑰。換金鑰要重新設定端點（GPO／重新安裝）。建議一開始就設定兩把：一把日常用，一把離線備援。

### 1.2 成功標準

- 強制簽章的端點，收到沒有簽章、簽章不符或欄位被改過的腳本／套件，一律不執行，並回報失敗原因。
- 簽章涵蓋所有影響「執行什麼」的欄位：腳本的內容雜湊、語言、逾時；套件的雜湊、大小、類型、安裝／移除參數、MSI ProductCode。
- 伺服器無法改變端點信任的公鑰。

## 2. 簽章格式（`protocol::signing`）

- 被簽的位元組：網域分隔字串 `endpoint-manager signed artifact v1\n` 加上下列結構以 serde_json 序列化（欄位順序固定）的結果：
  - 腳本：`{"kind":"script","sha256":<小寫>,"language":"powershell|sh","timeout_minutes":N}`
  - 套件：`{"kind":"package","sha256":<小寫>,"size":N,"package_kind":"msi|exe","install_args":"…","uninstall_args":"…","msi_product_code":null|"…"}`
- **Agent 以收到的欄位自己重組**被簽的內容再驗證，不採用伺服器提供的任何「已組好的內容」。
- 公鑰：32 bytes 原始 Ed25519 公鑰的 Base64（44 字元）。金鑰 ID：公鑰 SHA-256 的前 16 個十六進位字元。
- 簽章字串：`<金鑰 ID>:<64 bytes 簽章的 Base64>`。Agent 依金鑰 ID 找公鑰；找不到或驗證失敗即視為無效。
- 驗證用 `ring`（已在依賴樹裡，Agent 不增加新的密碼學套件）。

## 3. 簽章工具 `endpoint-sign`

新的 crate `crates/sign`，Windows 與 Linux 都提供執行檔。

| 指令 | 作用 |
|---|---|
| `endpoint-sign keygen <金鑰檔>` | 產生金鑰，從 stdin 讀密語（至少 12 字元），印出公鑰與金鑰 ID |
| `endpoint-sign pubkey <金鑰檔>` | 印出公鑰（不需密語） |
| `endpoint-sign sign <金鑰檔> <簽章請求.json> [--file <安裝檔>]` | 顯示要簽的內容摘要，讀密語後印出簽章字串 |

- **金鑰檔**：JSON，包含公鑰，以及用密語加密的私鑰（Argon2id 推導金鑰、ChaCha20-Poly1305 加密 PKCS#8）。檔案外洩但密語沒外洩時，私鑰仍然安全。
- **簽章請求**：伺服器提供下載的 JSON，內含要簽的欄位；腳本另外附上完整內容。
- 工具**自己計算**腳本內容的 SHA-256，跟請求裡的雜湊比對，不符就拒絕；並把腳本內容全文印出，讓簽章者看到自己簽的是什麼。
- 套件可以加 `--file` 指定簽章者手上的安裝檔（例如從原廠下載的），工具比對雜湊與大小；沒給時印出警告，提醒簽章者只是在相信伺服器上的檔案。

## 4. Agent

- `config.json` 新增 `signing_keys`（公鑰陣列），**只能在本機設定**：
  - Windows：MSI 屬性 `SIGNING_KEYS`（逗號分隔）。有值就取代原本的清單；空白就沿用。可以用 GPO 指派時的 transform 或 `msiexec … SIGNING_KEYS=…` 指定。
  - Linux：`endpoint-agent configure … --signing-key <公鑰>`（可重複）。
  - 格式錯誤的公鑰讓安裝／設定失敗，不會默默變成「不強制」。
- 清單非空就強制：
  - 腳本：雜湊相符之外，還要有可以用信任公鑰驗證的簽章，否則回報失敗「這台電腦要求簽章：…」，不執行。
  - 套件：安裝與移除前都驗證，失敗跟其他「執行前失敗」一樣回報（計入失敗次數與自動暫停）。
- 報到時回報公鑰清單（`CheckinRequest.signing_keys`，空的不送）。伺服器只拿來顯示與預先檢查，不影響 Agent 的判斷。

## 5. 伺服器

- 資料表：`scripts.signature`、`packages.signature`、`command_runs.script_signature`（建立指令時快照）、`devices.signing_keys TEXT[]`。
- 腳本內容或逾時一改就清除簽章（跟核准一樣）。套件的安裝／移除參數或 ProductCode 一改就清除簽章。
- 下發：`ScriptSpec.signature`、`PackageSpec.signature`（沒有就不送；舊 Agent 忽略）。
- **腳本詳細頁、套件詳細頁**（平台管理員）：
  - 「下載簽章請求」：`/scripts/{id}/signing-request.json`、`/packages/{id}/signing-request.json`。
  - 「上傳簽章」表單：貼上簽章字串。伺服器用端點回報過的公鑰預先驗證；驗證不過就拒絕；還沒有端點回報公鑰時，只檢查格式並提示「無法預先驗證」。
  - 顯示簽章狀態：已簽章（金鑰 ID）、未簽章。
  - 腳本必須**先核准**才能上傳簽章（簽章是核准之後的另一道確認，不是取代核准）。
- 稽核記錄：`script_signed`、`package_signed`。
- 裝置頁顯示「要求簽章：是（金鑰 ID…）／否」。
- 指令頁與派送頁：選到未簽章的腳本或套件，而範圍內有強制簽章的端點時，顯示警告與台數。

## 6. 分成兩個 PR

1. 協定、`endpoint-sign`、Agent 強制與設定（MSI 屬性、Linux `configure`）、報到回報公鑰、CI 建置工具。
2. 伺服器：資料表、儲存與下發簽章、簽章請求下載、上傳與預先驗證、畫面與 README。

兩個 PR 都合併後才發佈，避免出現「Agent 已強制、伺服器還不會送簽章」的版本。

## 7. 測試

- 協定：簽章與驗證來回、任一欄位被改都驗證失敗、金鑰 ID 不符、格式錯誤的簽章字串、網域分隔字串不同就失敗。
- 工具：金鑰檔加解密來回、錯誤密語、腳本內容與雜湊不符時拒絕、`--file` 雜湊不符時拒絕。
- Agent：沒設定公鑰時照舊執行；設定後，未簽章、錯誤簽章、欄位被改的腳本與套件都不執行並回報原因；正確簽章照常執行。設定合併（有值取代、空白沿用、格式錯誤失敗）。
- 伺服器：簽章隨內容變更清除、上傳前預先驗證、未核准不能上傳、下發欄位、報到儲存公鑰、權限。
