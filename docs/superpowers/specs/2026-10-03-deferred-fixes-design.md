# 收尾：第一～七期延後問題

日期：2026-10-03

## 1. 目標與範圍

第一～七期審查時延後的小問題約 90 項（記錄在各期審查結論，不在 repo 中）。使用者決定：

- 處理**前兩類**：影響使用者、安全或維運的問題，以及體驗／一致性的小瑕疵。
- 第三類（測試補強、刻意保留的設計）只補成本低的測試；刻意保留的設計在本文件寫明理由後結案。
- 舊的稽核紀錄（`notify_settings` 的完整 webhook 網址）**保持原樣**，不改寫。

成功標準：

- 下表標為「修」的每一項都有一個先失敗再通過的測試（文件、範本文字等無法測試的項目除外，在計畫中註明）。
- 不新增依賴；不改協定欄位的意義（新增欄位一律 `#[serde(default)]`）。
- 分三個 PR，各自走「計畫 → 實作 → 獨立審查 → PR → 合併」；全部完成後升版為 0.7.1 並發布。

## 3. 計畫 24：遠端指令

| # | 問題 | 處理 |
|---|---|---|
| 24-1 | 資料庫等非權限錯誤原文顯示為 409／422 | 權限錯誤 403、驗證錯誤 422、找不到 404；其餘記錄 error 後回 500，畫面只顯示「伺服器錯誤」。以型別區分錯誤，不比對錯誤字串 |
| 24-2 | 延遲時間格式錯誤時默默改成 10 分鐘 | 回 422 |
| 24-3 | 群組管理員對不存在的群組或錯誤的到期日得到 422，可藉此探測群組 id 是否存在 | 範圍檢查先於存在檢查，一律 403 |
| 24-4 | 指令詳情沒有「等待中」篩選 | 加上 |
| 24-5 | 清單不顯示已取消的指令；沒有剩餘對象的指令回 404 | 清單顯示已取消（標示狀態）；詳情頁照常顯示 |
| 24-6 | 已全部完成的指令仍顯示「取消」按鈕，伺服器也接受取消 | 沒有未完成對象時不顯示按鈕，伺服器回 409 |
| 24-7 | 腳本 textarea 會吃掉開頭的換行，導致內容改變需要重新核准 | 範本在 `<textarea>` 後保留一個換行 |
| 24-8 | 輸出接近 64 KiB 上限時，「逾時」前綴可能被截掉 | 截斷時先保留前綴的空間 |
| 24-9 | Agent 在腳本執行中停止，`scripts\` 留下腳本檔 | 啟動時清除 |
| 24-10 | 同一批指令中延遲 0 的重新開機會打斷後面的腳本 | 同一批中重新開機／關機最後執行 |
| 24-11 | 延遲 0 的重新開機沒有 `/f`，可能被應用程式擋住 | 延遲 0 時加 `/f`（延遲大於 0 時 Windows 本來就隱含 `/f`） |
| 24-12 | 「重新收集」用 `try_send`，佇列滿時可能漏掉區段 | 改為等待送出 |
| 24-13 | Agent 沒回報出去的指令紀錄永不清除，狀態檔會一直變大 | 開始超過 31 天的紀錄一律清除（指令最長 30 天過期，伺服器之後不再接受結果）；已回報的維持 30 天 |
| 24-14 | 資料表缺少 CHECK（腳本欄位只用於腳本、延遲只用於重開機／關機） | migration 加上 CHECK |
| 24-15 | 指定裝置時的範圍檢查沒有鎖住裝置列，可能同時被移到別的群組 | 檢查時 `FOR SHARE` |
| 24-16 | 稽核缺少修改前的值（舊 SHA-256、舊設定值） | 補上 |
| 24-17 | 輸出與說明沒有過濾 Unicode 格式字元（例如 U+202E 反轉方向） | 過濾 Cf 類字元（保留換行與 Tab） |
| 24-18 | loadsim `commands` 沒有檢查預期台數；`commands_setup.sql` 永久移動 5,000 台到測試群組 | 加檢查；SQL 結尾說明如何還原 |
| 24-19 | 測試缺少：混合範圍時的主機名稱與台數、詳情頁的 `<script>` 跳脫 | 補測試 |

不修（結案）：

- 過期後 5 分鐘內仍接受結果：刻意保留的寬限，避免報到與到期時間交錯時遺失結果。
- `shutdown.exe` 在回報成功後失敗看不到：先回報再執行是為了避免重開兩次；失敗時裝置仍在線上，下次報到即可看出沒有重開機。README 已說明。
- 背景迴圈（`run_command_worker`）沒有測試：邏輯在 `pass` 已測，迴圈只負責排程。

## 4. 計畫 25：軟體派送與 Windows Update

| # | 問題 | 處理 |
|---|---|---|
| 25-1 | 派送清單的失敗台數跨所有 revision，自動暫停只看目前 revision | 清單與詳情只計目前 revision，舊 revision 另外標示 |
| 25-2 | 安裝成功後若被其他工具一直移除，會無限重裝 | 24 小時內同一 revision 成功安裝 3 次後不再重裝，回報失敗「安裝後一再被移除」 |
| 25-3 | 回報結果時伺服器回 404（派送已刪除）會被當成暫時錯誤一直重送 | 404 視為完成，不再重送 |
| 25-4 | 一輪處理中所有指派共用開始時的 `now` | 每個指派使用當下時間 |
| 25-5 | `msiexec` 路徑由 `%SystemRoot%` 環境變數組成 | 改用 `GetSystemDirectoryW` |
| 25-6 | `<sha>.log` 安裝紀錄永遠保留 | 超過 30 天刪除 |
| 25-7 | 沒有「移除」的端對端測試 | 補測試 |
| 25-8 | 更新原則：錯誤分類不看 `policy_id`、衝突分類不看 revision，換群組或修改後短暫算錯 | 分類條件加上 |
| 25-9 | 更新原則：對不存在的 id POST 回 409／422 | 回 404 |
| 25-10 | 只填寬限、沒填期限時，寬限被默默丟掉 | 回 422 |
| 25-11 | 停用裝置的更新分頁顯示「不受管」 | 顯示「已停用」 |
| 25-12 | `patch_age` 規則用 UTC 日期比較，修補的安裝日期是裝置本地日期 | 改用管理網頁的顯示時區（`display_offset`）日期比較 |
| 25-13 | `store.rs` 的 SQL 字串有多餘空白 | 清掉 |
| 25-14 | loadsim 測試固定等 5.5 秒 | 改為使快取失效 |
| 25-15 | Agent：原則釋放後回報的 `policy_id` 仍是舊的 | 釋放後回報 None |
| 25-16 | Agent：讀登錄檔暫時失敗時短暫回報「衝突」 | 讀取失敗回報「錯誤」 |
| 25-17 | 原則設定無法解析時默默略過（裝置變成不受管） | 記錄 error，原則頁顯示「設定無法解析」 |
| 25-18 | 暫停日期可以是任何日期；極端的過去日期造成 500 | 只接受今天往前 35 天內，其他回 422 |
| 25-19 | 稽核缺少修改前的設定與被移除的群組 | 補上 |
| 25-20 | 同時編輯同一個原則時後存的覆蓋先存的 | 表單帶 revision，不符時回 409 並提示重新整理 |
| 25-21 | 群組頁「規則」欄也計入更新原則 | 欄名改為「規則與原則」 |

不修（結案）：

- 派送清單沒有分頁：派送數量少（每個派送都是人工建立）。
- 報到時多一次裝置查詢、快取重新載入的競爭（最多 5 秒）：負載測試報到 p99 在標準內；競爭會在下次確認 generation 時自行修正。
- 原則釋放時刪除與 GPO 相同的值、狀態檔遺失時留下的值：Agent 無法分辨值是誰寫的。README 已要求受管群組不要再用 GPO 管 Windows Update，另外補上「狀態檔遺失時的手動清理」說明。
- 錯誤狀態回報舊 revision：網頁已依此顯示，屬已知行為。
- 背景迴圈 `run_worker` 沒有測試：同 24 的理由。

| 26-24 | 範本重複判斷靠比對錯誤字串 | 以型別判斷 |
| 26-25 | 表單往返測試缺少 Defender 防竄改與密碼最長使用期限 | 補測試 |

| 26-27 | `interrupted_install_counts_as_attempt` 在全套件負載下偶爾逾時 | 改為等待「執行中」狀態寫入，不用固定 500 毫秒 |

不修（結案）：

- 舊稽核紀錄的 webhook 網址：使用者決定保持原樣。
- 豁免天數超出 1～365 時拒絕：這是之前修正後的行為，不是問題。
- `approve_is_not_blocked_by_key_share` 在高負載下偶爾逾時：測試環境的連線池問題，不是產品問題。
- 換發競爭沒有決定性的測試：無法以 HTTP 穩定重現，已以程式碼推理驗證。
- 1618 後沿用本機檔案時沒有下載來源：該次確實沒有下載，沒有來源是正確的。
- 先前列為「不做」的項目（網頁產生的 MSI 簽章、trigram 索引成本、真實瀏覽器測試）維持不做。
