# 網路介面、多重連線偵測與本機事件暫存 設計

日期：2026-11-22。狀態：等使用者審閱。

標「（設計者決定）」的項目是我做的決定，使用者沒有特別表示意見，審閱時可以推翻。

## 1. 目的

1. **看得到每張網卡**：現在 Agent 只回報 IP 清單，伺服器只存第一個 IP，看不出網卡種類，也看不出哪張網卡有預設閘道。
2. **偵測多重連線（dual-homed）**：電腦同時接公司網路和外部網路（4G 網卡、手機熱點、家用 Wi-Fi），等於繞過公司的防火牆。
3. **不漏掉短暫的狀況**：插上 4G 幾分鐘就拔掉，剛好落在兩次報到之間時，現在完全看不到。Agent 改成在本機監看網路變化、把事件暫存在本機，下次報到時一起送出；連不上伺服器時也先存著，恢復後補送。
4. **報到與收集間隔可以在後台設定**：現在只能直接改資料庫的 `settings` 資料表。

### 1.1 範圍

**做：**
- 新區段 `network`：每張網卡的種類、狀態、IP、預設閘道、DNS。
- Agent 監看網路變化，寫進本機事件日誌，報到時上傳，伺服器確認收到後才刪除。
- 伺服器判斷多重連線：目前狀態和過去事件都看。
- 後台：裝置頁「網路」分頁、裝置清單篩選、時間軸、合規規則「多重連線」。
- 裝置的所有 IP 都存起來，搜尋時任何一個 IP 都找得到。
- 系統設定頁可以調整報到與收集間隔。

**不做：**
- 阻擋連線，或自動停用網卡（偵測與告警而已）。
- 流量內容、連線紀錄（哪個程式連到哪裡）。
- 每個群組各自的間隔設定（設計者決定：有了事件暫存之後，不需要為了「抓到短暫狀況」而縮短間隔；需要的話另開規格）。
- 把事件日誌用在網路以外的事情（USB 插拔等）。日誌格式預留了事件種類，之後要加再另開規格。

## 2. 目前的報到與收集間隔

| 項目 | 預設 | 下限 | 設定鍵 |
|---|---|---|---|
| 報到（心跳、取得指令與派送） | 60 秒 | 30 秒 | `checkin_interval_secs` |
| 軟體、更新、服務、安全、登錄檔 | 1 小時 | 5 分鐘 | `*_interval_secs` |
| 硬體 | 24 小時 | 5 分鐘 | `hardware_interval_secs` |

- 全部裝置共用同一組值，伺服器在每次報到的回應裡下發，改了之後 Agent 下次報到就生效。
- 目前沒有設定畫面。§7 補上。

## 3. `network` 區段

```
NetworkInfo { interfaces: Vec<NetInterface> }
NetInterface {
  name: String,              // Windows 的別名（「乙太網路」）或 Linux 的 eth0
  description: Option<String>,
  kind: NetKind,             // ethernet | wifi | cellular | vpn | virtual | loopback | other
  up: bool,
  mac: Option<String>,
  addresses: Vec<String>,    // CIDR 寫法：10.1.2.3/24
  gateways: Vec<String>,     // 這張網卡上的預設閘道
  dns: Vec<String>,
  ssid: Option<String>,      // Wi-Fi 才有，讀不到就 None
}
```

### 3.1 網卡種類怎麼判斷

**Windows**：使用 `GetAdaptersAddresses`。
- `IfType` 是 `IF_TYPE_IEEE80211` → `wifi`；`IF_TYPE_WWANPP`、`IF_TYPE_WWANPP2` → `cellular`。
- `IF_TYPE_PPP`、`IF_TYPE_TUNNEL`，或描述含常見 VPN 名稱（WireGuard、OpenVPN、Cisco AnyConnect、FortiClient、GlobalProtect）→ `vpn`。
- Hyper-V vEthernet、WSL、Docker、VirtualBox、VMware 的虛擬網卡 → `virtual`。
- 其餘 `IF_TYPE_ETHERNET_CSMACD` → `ethernet`。
- 預設閘道讀 `FirstGatewayAddress`。SSID 用 `WlanQueryInterface`，讀不到不算錯誤。

**Linux**：
- `/sys/devices/virtual/net/` 底下的網卡（bridge、veth、docker0、virbr0 等）→ `virtual`，`tun`、`wg` 開頭的 → `vpn`。
- 有 `/sys/class/net/<名稱>/wireless` → `wifi`。
- `/sys/class/net/<名稱>/device/driver` 是 `cdc_mbim`、`qmi_wwan`、`cdc_ether`、`rndis_host`（USB 網卡與手機分享）→ `cellular`。
- 其他實體網卡 → `ethernet`。
- 位址與閘道：`ip -j addr`、`ip -j route show default`。

判斷規則放在 `protocol` 之外的純函式，用表格測試。少見的網卡判斷錯了，使用者可以在合規規則裡設定例外（§5.3）。

### 3.2 收集頻率

區段本身照一般區段處理：雜湊相同就不上傳，間隔使用 `services_secs`（設計者決定）。即時性靠 §4 的事件，不靠縮短收集間隔。

## 4. 本機監看與事件暫存

### 4.1 監看

- **Windows**：`NotifyIpInterfaceChange` 與 `NotifyUnicastIpAddressChange`，有變化時通知 Agent。
- **Linux**：每 15 秒讀一次 `/sys/class/net` 與路由表，跟上一次比較（設計者決定：比監聽 netlink 簡單，每次只讀幾個小檔案，成本可以忽略）。
- 收到通知後等 3 秒再讀（網卡啟用時位址與閘道會分幾次出現），比較前後兩份 `NetworkInfo`，有差異就寫事件。

### 4.2 事件

```
AgentEvent {
  seq: u64,                  // 本機遞增
  at: OffsetDateTime,        // 端點時間
  kind: String,              // 第一版只有 "net.up" | "net.down" | "net.changed"
  data: serde_json::Value,   // 變化後的那張 NetInterface（net.down 只有 name 與 kind）
}
```

### 4.3 本機日誌

- 存在 Agent 狀態目錄的 `events.jsonl`，一行一筆，寫入後 `fsync`。日誌另外記一個 `journal_id`（UUID），重新安裝或檔案損毀時重新產生，伺服器用它分辨「序號歸零」與重送。
- **上限**：最多 5,000 筆、30 天（設計者決定），超過就刪最舊的，並記一筆 `journal.dropped`（附刪掉的筆數），讓後台知道有缺漏。
- 檔案壞掉的行跳過，不影響其他行。
- 權限與 `state.json` 相同（只有 SYSTEM／root 能讀寫）。

### 4.4 上傳與確認

- 報到請求新增 `events: Vec<AgentEvent>` 與 `journal_id`，一次最多 200 筆，從最舊的開始送。
- 回應新增 `events_ack: Option<u64>`：伺服器已存下的最大序號。Agent 收到後才刪除 `seq ≤ ack` 的事件。報到失敗就不刪，下次重送。
- 伺服器以 `(device_id, journal_id, seq)` 為唯一鍵，重送的事件直接略過。
- 還有未送的事件時，Agent 在 5 秒後再報到一次，直到送完（設計者決定：離線很久後回來能很快補齊，又不會一次塞爆單一請求）。
- 端點時鐘可能不準：伺服器同時記下收到的時間；端點時間比收到時間晚超過 5 分鐘時，以收到時間為準。

### 4.5 相容性

- 回應新增 `supports_events: bool`，舊版伺服器沒有這個欄位。Agent 只在看到它時才上傳事件；在那之前只寫本機日誌（受 §4.3 的上限限制），伺服器升級後就會補送。
- `network` 區段的相容做法跟容器規格 §4.1 一樣，靠 `supported_sections` 判斷伺服器是否支援。
- 舊版 Agent 不送 `events`，伺服器照常處理。

## 5. 多重連線判斷

### 5.1 定義

符合下列任一條件，就是**多重連線**：

1. **兩條對外路徑**：兩張以上 `up` 的網卡**都有預設閘道**，而且種類不是 `virtual`、`loopback`、`vpn`。
2. **跨越據點網段**：一張網卡的位址在某個據點的網段內，另一張有預設閘道的網卡，位址不在任何據點網段內，而且種類不是 `virtual`、`loopback`。這需要在「據點」設定網段；沒設定任何據點時只用條件 1。

VPN 不計入條件 1（設計者決定）：在外連 VPN 回公司是正常用法。條件 2 會計入 VPN 以外的網卡，所以「公司網路＋手機熱點」仍然抓得到。

### 5.2 目前狀態與過去事件

- **目前狀態**：用最新的 `network` 區段判斷，寫在 `devices.dual_homed`（布林）。
- **過去事件**：伺服器依時間順序重播事件，得出每台裝置「多重連線」的起訖時間，存成 `device_dual_homed_periods (device_id, started_at, ended_at, detail)`。短暫插上又拔掉的情況就是一段很短的期間。
- 事件有缺漏時（`journal.dropped`），期間標記為「可能不完整」。

### 5.3 合規規則「多重連線」 `dual_homed`

| 參數 | 預設 | 說明 |
|---|---|---|
| 回溯天數 | 7 | 這段期間內只要出現過一次就算違規 |
| 最短持續時間 | 0 秒 | 短於這個值的期間不計（排除切換網路時的瞬間重疊） |
| 例外網卡名稱 | 空 | 萬用字元，例如 `*Npcap*` |
| 例外網段 | 空 | CIDR，例如測試網段 |
| 只看條件 2 | 否 | 只抓「公司網路＋外部網路」的組合 |

- 違規明細列出最近 5 段期間：開始時間、持續多久、涉及哪些網卡與位址。
- 沒有 `network` 區段（舊版 Agent）的裝置：未知，原因是「Agent 版本過舊」。
- 違規期間結束、超過回溯天數後，自動恢復符合。

## 6. 後台

- **裝置頁「網路」分頁**：
  - 網卡表格：名稱、種類、狀態、位址、閘道、DNS、SSID。有閘道的網卡標出來。
  - 下方是「多重連線紀錄」：期間、持續時間、涉及的網卡。
- **裝置頁的狀態卡與問題清單**：目前或 7 天內有多重連線時，加入問題清單。
- **時間軸**：網卡啟用、停用、位址改變，以及多重連線的開始與結束。
- **裝置清單**：
  - 篩選新增「多重連線（目前）」與「多重連線（7 天內）」。
  - 「IP」欄顯示主要位址，滑過會顯示全部；搜尋任何一個位址都找得到這台裝置。
- **據點頁**：「依 IP 判斷據點」改用所有位址。一台裝置符合多個據點時，以第一張有閘道的網卡為準。

### 6.1 所有 IP 的儲存

- `devices.ip` 保留，仍是「主要位址」：有預設閘道的第一張實體網卡上的第一個 IPv4；沒有 `network` 區段時沿用現在的做法。
- 新欄位 `devices.ips inet[]` 存報到時回報的全部位址，加 GIN 索引，讓搜尋用得上。

## 7. 間隔設定畫面

- 系統設定頁新增「報到與收集」區塊，只有平台管理員看得到。
- 欄位：報到間隔，以及各區段的收集間隔。下限與現在的程式一致（報到 30 秒、收集 5 分鐘），上限 7 天。
- 每個欄位旁顯示估算：報到間隔乘上目前的裝置數量，換算成每秒請求數。例如「目前 1,200 台，約每秒 20 次報到」。
- 儲存時寫稽核記錄。改動在各 Agent 下一次報到後生效。
- 報到間隔調大時，「離線」的判斷（目前是 3 倍報到間隔）自動跟著變，不用另外調整。

## 8. 測試

- **網卡種類判斷**：Windows 與 Linux 各一張表格，每種種類至少一筆，加上判斷不了的情況。
- **事件日誌**：
  - 寫入、重新開啟後序號延續。
  - 超過上限時刪最舊的並記 `journal.dropped`。
  - 壞掉的行跳過。
  - 重新安裝時更換 `journal_id`。
- **上傳**：
  - 有 ack 才刪除。
  - 報到失敗不刪。
  - 重送的事件被略過。
  - 舊版伺服器不送事件。
  - 一次最多 200 筆，有剩時 5 秒後再報到。
- **多重連線**：
  - 兩個條件各自成立與不成立的情況；VPN、虛擬網卡不計入。
  - 從事件重播出期間；最短持續時間與例外設定生效。
  - 事件缺漏時標記「可能不完整」。
- **後台**：網路分頁、裝置清單篩選、搜尋任何一個 IP、群組管理員範圍、設定頁的權限與稽核。

## 9. 分期

1. **`network` 區段與所有 IP 的儲存**（§3、§6.1），加上裝置頁「網路」分頁。依目前狀態判斷多重連線（§5.1）。
2. **事件暫存與上傳**（§4），時間軸，過去期間的判斷（§5.2）。
3. **合規規則**（§5.3）、裝置清單篩選、問題清單。
4. **間隔設定畫面**（§7）：跟其他期沒有相依，可以隨時插進來做。

建議接在容器規格第一期（判斷 Agent 在哪裡執行）之後，兩份規格都要在報到回應裡加上「伺服器支援哪些區段」的欄位，一起做比較省事。
