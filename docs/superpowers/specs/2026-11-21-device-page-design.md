# 裝置頁重新編排（UI 改版第三期）

日期：2026-11-21
前身：`2026-10-03-ui-redesign-design.md` §1.1 第三期。

## 1. 範圍

**做：**
- 頁首摘要：群組、作業系統、IP、最後回報（相對時間）。
- 狀態卡：一眼看出這台的合規、更新、派送與連線狀態。
- 問題清單：這台目前需要處理的事，依嚴重度排序，連到對應的分頁。
- 時間軸分頁（預設分頁）：把散在各處的歷史合併成一條，依時間倒序，可往前載入。

**不做：**
- 修改既有分頁的內容、網址或權限。
- 新增歷史資料的來源（只整理既有記錄）。
- 搜尋結果頁改版（原規劃在第三期，另案處理；目前的裝置清單已可搜尋）。

**限制：** 沿用第一、二期（CSP 不允許 inline style／script；沒有 JS 時主要內容可讀）。
**權限：** 與現行裝置頁相同（範圍外回 404）。

## 2. 頁首與狀態卡

- 標題列下加一行：群組・作業系統・IP・「最後回報 N 分鐘前」。
- 狀態卡（Windows）：
  | 卡片 | 內容 | 狀態色 |
  |---|---|---|
  | 連線 | 在線／離線，最後回報的相對時間 | 在線綠、離線灰、離線超過 7 天紅 |
  | 合規 | 違規規則數（其中高風險幾條）；沒有違規顯示「合規」 | 有高風險紅、有違規黃、合規綠 |
  | 更新 | 最後安裝修補的日期、是否等待重新開機 | 等待重開機超過 7 天紅、等待中黃 |
  | 派送 | 成功／失敗台次 | 有失敗紅 |
- Linux 只有「連線」卡，再加「開機時間」與「Agent 版本」兩張資訊卡；不出現 Windows 專屬分頁的連結。

## 3. 問題清單

| 嚴重度 | 項目 |
|---|---|
| 依規則 | 每條違反的規則（名稱、開始時間） |
| 高 | 每個失敗的派送（名稱、訊息） |
| 高 | 離線超過 7 天 |
| 中 | 等待重新開機（超過 7 天為高） |
| 中 | 更新原則衝突或錯誤（附說明） |
| 中 | 疑似重複、待核准 |
| 中 | 近 7 天失敗的遠端指令 |
| 低 | 合規結果無法判斷的規則 |
| 低 | 各區段的收集錯誤（取代原本的「收集錯誤」卡片） |

沒有問題時顯示「沒有發現問題」。

## 4. 時間軸

來源（每種最多取 50 筆，合併後取最新 50 筆）：

| 來源 | 事件 |
|---|---|
| `violation_events` | 開始違反、恢復合規、豁免、無法判斷 |
| `inventory_changes` | 同一次上傳、同一區段合併成一筆：「軟體：新增 2、移除 1、更新 3」，附前三個項目名稱 |
| `command_targets` | 遠端指令的結果（成功、失敗、過期、取消、已送出） |
| `deployment_status` | 派送的最新結果 |
| `audit_log`（target＝裝置 ID） | 管理動作：核准、拒絕、除役、移動群組、新增／撤銷豁免 |
| `devices.enrolled_at` | 註冊 |

- 依管理網頁時區的日期分組，每筆顯示時間、圖示類別、標題、說明，可連到對應的分頁。
- 「載入更早的事件」：`GET /devices/{id}/timeline?before=<RFC 3339>`，只取早於該時間的事件（htmx 接在清單後面）。
- 新增索引 `audit_log (target, at DESC)`，讓裝置的管理記錄查詢不需要掃整張表。
- 派送只有最新狀態，沒有歷程；指令以完成時間（沒有就用送出、建立時間）排序。

## 5. 測試

- 問題清單：違規、派送失敗、等待重開機、收集錯誤都會出現；沒有問題時顯示「沒有發現問題」。
- 狀態卡：合規、更新、派送數字正確；Linux 沒有 Windows 專屬分頁的連結。
- 時間軸：各來源事件都出現且依時間倒序；同一次上傳的軟體變更合併；`before` 分頁正確；範圍外 404。
- 既有裝置頁測試維持通過。
