# 待辦與未來方向

依預定順序排列。每一項開始前另寫規格，經確認後再實作。

## 1. 網路設備資訊（由分點快取主機收集，不做主動掃描）

規格：`docs/superpowers/specs/2026-11-23-network-devices-design.md`。

- 分點快取主機用 SNMP 唯讀查詢管理員登錄的交換器、路由器、AP：型號、韌體、埠的狀態、MAC 位址表、ARP 表、LLDP 鄰居。
- 用途：
  - 知道電腦接在哪台交換器的哪個埠。
  - 找出網路上有、但沒裝 Agent 的設備。
  - 提供電腦本身改不了的資料，給第 2 項比對。
- 不 ping、不掃埠、不掃網段，只查詢明確登錄的設備。

## 2. 偵測本機資料竄改（加強版，接在第 1 項之後）

原本的規格（序號缺口、日誌 ID 頻繁更換）只擋得住粗糙的竄改，要加強後重寫。

電腦上有管理員權限的人能控制那台電腦上的一切。所以加強的方向是兩件事：
- **縮短能動手的時間**。
- **加上不是從那台電腦來的證據**。

做法：

1. **事件立即上傳**：有事件就在幾秒內送到伺服器，送到之後本機怎麼改都沒用。想刪紀錄，就只能在事件發生前先停掉 Agent。
2. **抓「Agent 被停掉」**：交換器上還看得到這台電腦的 MAC，Agent 卻沒報到，就標示（需要第 1 項）。
3. **網路端交叉比對**：Agent 回報的 IP、MAC 跟交換器的 ARP 表、MAC 表不一致，就標示（需要第 1 項）。
4. **作業系統紀錄**：
   - Windows：稽核紀錄被清除（事件 1102、104）、Agent 服務被停止或改成停用。
   - Linux：journald。
   - 清除紀錄這個動作本身也會留下紀錄，Agent 即時回報。
5. **序號缺口與日誌重建**：保留，當作最基本的一層。

TPM 金鑰與遠端證明仍留待之後。

## 3. 擴增錯誤設定（misconfig）偵測

現有的「組態基準範本」已經用登錄檔、安全設定涵蓋一部分 Windows 設定（SMBv1、SMB 簽章、LLMNR、NLA、WDigest、匿名列舉、LSA 保護、UAC、自動執行等）。這一項補上目前**看不到**的錯誤設定。

原則：

- **只回報判斷結果，不上傳內容**：例如只回報「這個共用 Everyone 可寫入」，不上傳檔案清單；自動登入只回報「有存密碼」，不讀密碼本身。
- 每一類都做成合規規則種類（或範本），沿用現有的違規、豁免、通知、報告。
- 先做風險最高、收集最便宜的。

### 2.1 現有資料就能判斷（只改伺服器）

- **服務路徑沒加引號**：路徑有空白、沒加引號的服務可被提權（服務區段已有 `binary_path`）。
- **Linux sudo 免密碼全權**：`NOPASSWD: ALL`（帳號區段已收集 sudoers）。
- **Linux 有第二個 UID 0 帳號、或空密碼帳號**（帳號區段）。
- **基準範本補幾條登錄檔項目**：AlwaysInstallElevated、WinRM 允許 Basic／未加密、自動登入存了密碼（只判斷值存在）、匿名可存取的具名管道與共用（NullSessionPipes／NullSessionShares）、停用 Guest 帳號。

### 2.2 需要 Agent 新收集

1. **共用資料夾（優先）**
   - Windows：SMB 共用清單，加上共用權限與 NTFS 權限中給 Everyone、Guests、Anonymous Logon、Authenticated Users、Domain Users 的「讀取／變更／完全控制」；Guest 帳號是否啟用（匿名實際可進入的條件）。
   - Linux：Samba 的 `guest ok`、`writable`、`map to guest`；NFS `/etc/exports` 的 `*`、`rw`、`no_root_squash`。
   - 規則：「匿名或所有人可寫入的共用」（高）、「匿名或所有人可讀取的共用」（中）、可設例外共用名稱。
2. **對外開放的服務**
   - 本機監聽的連接埠與程式（只收監聽在非 127.0.0.1 的）。
   - 規則：禁止的服務（Telnet、FTP、VNC、未加密的 SMB 對外）、資料庫監聽在所有介面（Redis、MongoDB、Elasticsearch、MySQL、PostgreSQL）。
   - Windows 防火牆有「任何來源、任何連接埠」的允許規則。
3. **遠端登入設定**
   - Linux `sshd` 實際生效的設定（`sshd -T`）：PermitRootLogin、PasswordAuthentication、PermitEmptyPasswords。
   - Windows 遠端桌面是否開啟、允許哪些群組登入。
4. **權限過寬（可被提權）**
   - Windows：服務執行檔或所在資料夾一般使用者可寫入、排程工作以 SYSTEM 執行使用者可寫入的程式。
   - Linux：`/etc` 下所有人可寫入的檔案、`/etc/shadow` 權限、非預期的 SUID 程式（與套件管理員的清單比對）。
5. **Windows 本機帳號**：密碼永不過期、不需要密碼的帳號（目前帳號區段只有 Linux）。

需要先決定：

- 新增區段（例如「共用與服務」）還是併入安全設定區段；收集頻率沿用「安全設定、帳號」的間隔。
- 權限判斷在 Agent 端做（只上傳結論）以減少資料量與敏感資訊。
- 每一類先寫規格，附上誤判情境（例如印表機共用、IT 刻意開放的軟體散布共用）與例外設定。

## 4. 依據點量測回報流量

- 伺服器依據點統計每個分點上傳的位元組數與請求數，在據點頁顯示。
- 同時統計連線品質：Agent 在報到時附上上次以來的請求失敗次數與逾時次數，伺服器依據點彙整。跨海的國外分點延遲高、會掉封包，有數據才知道要不要調整。
- 目的：先用數據判斷分點到總部的頻寬是否真的不足，再決定要不要做第 6 項的分點中繼。
- 背景：報到每次約 1–2 KB、盤點只上傳有變動的區段、上傳一律 gzip，平常流量應該不大；大流量的軟體套件已經由分點快取下載。

## 5. 依據點覆寫報到與收集間隔

- 頻寬小的分點可以設定比總部長的間隔，沿用「報到與收集」設定頁，加上據點層級的覆寫。
- 一併覆寫 Agent 的請求逾時（目前固定 60 秒）：延遲高、掉封包的國外分點上傳大的區段時可能逾時，造成該區段一直更新不了。資料不會遺失，但會一直過舊。

## 6. 分點中繼（視第 4 項的量測結果）

端點把資料送到分點，由分點彙整後批次送回總部。改動大，只在量測證明頻寬不足時才做：

- **身分**：Agent 對每份資料簽章、總部驗章，分點只轉送，不能偽造端點的資料。
- **即時性**：遠端指令與事件確認多一跳；分點離線時要暫存、續傳、去重。
- **分點主機變重要**：同時負責套件快取、SNMP、中繼，需要另外強化。
