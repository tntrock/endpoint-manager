# 待辦與未來方向

依預定順序排列。每一項開始前另寫規格，經確認後再實作。

## 1. 偵測本機資料竄改（網路規格 §10）

先做最便宜、最有效的兩項：

- **序號缺口**：本機事件日誌的序號應該連續，伺服器發現跳號時在裝置頁與時間軸標示。
- **日誌 ID 頻繁更換**：日誌被刪除重建時 `journal_id` 會換，短時間內多次更換列為可疑。

雜湊鏈、網路端交叉驗證、TPM 留待之後。

## 2. 依據點量測回報流量

- 伺服器依據點統計每個分點上傳的位元組數與請求數，在據點頁顯示。
- 目的：先用數據判斷分點到總部的頻寬是否真的不足，再決定要不要做第 4 項的分點中繼。
- 背景：報到每次約 1–2 KB、盤點只上傳有變動的區段、上傳一律 gzip，平常流量應該不大；大流量的軟體套件已經由分點快取下載。

## 3. 依據點覆寫報到與收集間隔

- 頻寬小的分點可以設定比總部長的間隔，沿用「報到與收集」設定頁，加上據點層級的覆寫。

## 4. 網路設備資訊（由分點快取主機收集）

分點快取主機已部署在每個分點、知道自己的網段，適合當收集點；端點的 Agent 不做掃描。

1. **SNMP 讀網路設備**：交換器、路由器、AP 的型號、韌體版本、介面狀態，可接合規規則（例如韌體過舊）。
2. **SNMP 讀 ARP 表與 MAC 位址表**：
   - 知道每個 IP／MAC 接在哪台交換器的哪個埠。
   - 列出「網路上有、但沒裝 Agent」的設備。
   - 從網路端交叉驗證 Agent 回報的網卡（竄改偵測、多重連線）。
3. **主動掃描**（預設關閉、每個據點各自開啟）：只掃據點網段，只做 ping 與少數埠，可限速。會觸發 IDS 告警、老舊印表機或工控設備可能當機，所以放最後。

需要先解決：

- SNMPv3 帳密的加密保存與發給分點。
- Rust 的 SNMP 套件對 v3 加密的支援，不足時改呼叫 net-snmp。
- 網路設備沒有 Agent 與憑證，另建「網路資產」資料模型。

## 5. 分點中繼（視第 2 項的量測結果）

端點把資料送到分點，由分點彙整後批次送回總部。改動大，只在量測證明頻寬不足時才做：

- **身分**：Agent 對每份資料簽章、總部驗章，分點只轉送，不能偽造端點的資料。
- **即時性**：遠端指令與事件確認多一跳；分點離線時要暫存、續傳、去重。
- **分點主機變重要**：同時負責套件快取、SNMP、中繼，需要另外強化。
